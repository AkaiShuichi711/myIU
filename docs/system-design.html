System Design Document

Tài liệu thiết kế hệ thống toàn diện cho myIU LMS — nền tảng quản lý học tập cấp đại học gồm hai ứng dụng độc lập: Portal dành cho sinh viên/giảng viên và Admin Panel dành cho quản trị viên, giao tiếp qua REST API và cơ sở dữ liệu PostgreSQL chung.

Java 21 · Spring Boot 3.4 React 18 · TypeScript · Vite PostgreSQL · Flyway Portal :8080 · Admin :8081 Microsoft SSO OAuth2 Docker · Nginx
Portal (myIU)
Backend :8080 · Frontend :5173 · Auth: Microsoft SSO
Admin (myIU-admin)
Backend :8081 · Frontend :3000 · Auth: email/password JWT
Database
PostgreSQL myiu_local / myiu_dev / myiu_prod · Schema owned by Portal (Flyway)
Shared Infrastructure
Caffeine cache · JWT blacklist · Bucket4j rate-limit · Virtual threads (Loom)

3.2 Sequence Diagram — Microsoft SSO Login

Luồng chi tiết xác thực OAuth2 PKCE với Azure AD, đồng bộ profile, và phát hành JWT tích hợp RequestIdFilter và LoginSession.

sequenceDiagram
    actor U as User (Browser)
    participant FE as Portal Frontend :5173
    participant BE as Portal Backend :8080
    participant RF as RequestIdFilter
    participant JF as JwtAuthFilter
    participant AZ as Microsoft Azure AD
    participant DB as PostgreSQL
    participant SS as SessionService

    U->>FE: Navigate to portal URL
    FE->>FE: Check JWT in localStorage
    FE->>U: Render /sign-in page
    U->>FE: Click "Sign in with Microsoft"
    FE->>AZ: Redirect to /oauth2/authorize?response_type=code&client_id=...

    AZ->>U: Show Microsoft login UI
    U->>AZ: Enter credentials
    AZ->>BE: GET /login/oauth2/code/azure?code=AUTH_CODE
    Note over BE,AZ: Spring Security OAuth2 Login handles callback

    BE->>RF: Request enters filter chain
    RF->>RF: Generate or read X-Request-ID
    RF->>RF: MDC.put("requestId", id)

    BE->>AZ: POST /oauth2/token — exchange code
    AZ->>BE: access_token + id_token
    BE->>AZ: GET /v1.0/me (Graph API)
    AZ->>BE: { email, displayName, id }

    BE->>DB: findByEmail(email)
    alt New user
        DB-->>BE: empty
        BE->>DB: INSERT user (authProvider=microsoft, roles=[student])
        DB-->>BE: saved User entity
    else Existing user
        DB-->>BE: User entity
    end

    BE->>SS: createSession(userId, ip, userAgent)
    SS->>DB: INSERT login_sessions
    BE->>BE: JwtTokenProvider.generate(userId, roles, jti=UUID)
    BE->>FE: Redirect with JWT in URL fragment / cookie
    FE->>FE: Store JWT → localStorage
    FE->>BE: GET /api/auth/me (Authorization: Bearer JWT)

    BE->>JF: Validate JWT
    JF->>JF: isRevoked(jti)? — JwtBlacklistService
    JF->>JF: Verify signature + expiry
    JF->>BE: Authentication set in SecurityContext

    BE->>DB: findById(userId)
    DB-->>BE: User
    BE->>FE: 200 { id, name, email, roles }
    FE->>U: Render Home page
3.3 Sequence Diagram — Assignment Submission & Grading

Tương tác đầy đủ giữa sinh viên, giảng viên, backend, và notification system trong vòng đời một bài tập.

sequenceDiagram
    actor SV as Student
    actor GV as Lecturer
    participant FE as Frontend :5173
    participant BE as Backend :8080
    participant ST as StorageService
    participant DB as PostgreSQL
    participant NS as NotificationService
    participant WS as WebSocket (STOMP)

    SV->>FE: Open course → select assignment post
    FE->>BE: GET /api/courses/{id}/posts (Bearer JWT)
    BE->>DB: findByCourseId + joinFetch submissions by studentId
    DB-->>BE: List CoursePost + submission status
    BE-->>FE: 200 posts[]

    FE->>SV: Show assignment with "Submit" button
    SV->>FE: Select file + click Submit
    FE->>BE: POST /api/storage/upload (multipart/form-data)
    BE->>ST: store(file) → generate storedName
    ST->>DB: INSERT stored_files
    DB-->>ST: StoredFile
    ST-->>BE: fileUrl
    BE-->>FE: 200 { fileUrl }

    FE->>BE: POST /api/assignment-submissions\n{ coursePostId, content, attachmentUrl }
    Note over BE: @Valid — constraints checked\n@PreAuthorize authenticated
    BE->>DB: INSERT assignment_submissions (status=submitted)
    DB-->>BE: saved submission (id)
    BE->>NS: notifyLecturer(post.authorId, submissionId)
    NS->>DB: INSERT notifications (userId=lecturerId)
    NS->>WS: convertAndSendToUser(lecturerId, payload)
    WS-->>GV: Real-time notification
    BE-->>FE: 201 Created { submission }
    FE->>SV: Show "Submitted" badge

    Note over GV: Lecturer reviews later
    GV->>FE: Open submission list
    FE->>BE: GET /api/assignment-submissions?coursePostId=X
    BE->>DB: findByPostId
    DB-->>BE: List submissions
    BE-->>FE: 200 submissions[]
    GV->>FE: Enter score 85 → click Grade
    FE->>BE: PUT /api/assignment-submissions/{id}/grade\n{ score: 85.0 }
    Note over BE: @PreAuthorize hasRole('lecturer')
    BE->>DB: UPDATE score=85, gradedBy, gradedAt
    DB-->>BE: updated
    BE->>NS: notifyStudent(submission.studentId, score)
    NS->>DB: INSERT notifications (userId=studentId)
    NS->>WS: convertAndSendToUser(studentId, payload)
    WS-->>SV: Real-time grade notification
    BE-->>FE: 200 OK
